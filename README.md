# MarketObserver Pro

نظام Telegram متعدد المستخدمين لتحليل الأسواق والتنبيهات والتداول الورقي، مع طبقة وسيط قابلة للإضافة لاحقًا. النسخة الحالية **لا تنفذ تداولًا حقيقيًا** ولا تستخدم أسعارًا اصطناعية عند فشل مزود البيانات.

## ما تم بناؤه

يحتوي المشروع الآن على طبقة أصول موحدة تدعم العملات الرقمية، الفوركس، الذهب والفضة، النفط، الأسهم وبعض المؤشرات، مع أسماء عربية وإنجليزية ورموز مزود البيانات. طبقة البيانات تستخدم Binance للعملات الرقمية عند توفر الرمز، وYahoo Finance لبقية الأصول، مع cache قصير وفشل واضح بدل اختلاق أسعار.

محرك التحليل يحسب RSI بطريقة Wilder، وSMA20 وSMA50 وATR14، ويستخرج نطاق الدعم والمقاومة من آخر 50 شمعة. النتائج وصفية وموسومة بوقت آخر شمعة وعدد البيانات، ولا تعرض وعدًا بالربح.

يوجد تخزين دائم عبر SQLAlchemy يدعم SQLite للتجارب وPostgreSQL عند النشر، ويخزن المستخدمين، اللغة، آخر أصل، التنبيهات، الحساب الورقي، والصفقات الورقية. التنبيهات تقرأ السعر مرة لكل أصل في كل دورة بدل تكرار الطلب لكل مستخدم، وتدعم `/alert`, `/alerts`, و`/cancel_alert`.

يوجد أيضًا `/paperbuy` و`/papersell` لتسجيل صفقات محاكاة فقط. طبقة `Broker` معزولة داخل `marketobserver/broker.py`، وتحتوي حاليًا على `PaperBroker` ورفض آمن لأي وسيط حقيقي غير مهيأ.

## الأوامر الأساسية

| الأمر | الاستخدام |
|---|---|
| `/start` | تسجيل المستخدم وعرض الإرشادات |
| `/analyze BTC` | تحليل أصل محدد |
| `/chart BTC` | إنشاء شارت من بيانات حقيقية |
| `/risk 10000 1 65000 63000` | حساب وحدات نظرية مع سقف المخاطرة |
| `/alert above BTC 70000` | تنبيه عند تجاوز السعر |
| `/alert below XAUUSD 2300` | تنبيه عند هبوط السعر |
| `/alerts` | عرض تنبيهات المستخدم |
| `/cancel_alert 1` | إلغاء تنبيه نشط |
| `/paperbuy BTC 0.01 60000 70000` | صفقة شراء محاكاة |
| `/papersell BTC 0.01 70000 60000` | صفقة بيع محاكاة |
| `/broadcast نص الإعلان` | إرسال رسالة لكل المستخدمين النشطين (للمشرف فقط) |
| صورة بوصف `/broadcast نص الإعلان` أو `/broadcast_photo نص الإعلان` | إرسال الصورة ووصفها لكل المستخدمين النشطين (للمشرف فقط) |

## إرسال رسالة جماعية `/broadcast`

الأمر `/broadcast نص الإعلان` مخصص للمشرفين، ويُرسل إلى كل مستخدم نشط في جدول `users` نفسه الذي يكتب فيه `/start`. يُعرَّف المشرف بإحدى طريقتين: إضافة `chat_id` الخاص به إلى `ADMIN_CHAT_IDS` (أرقام مفصولة بفواصل)، أو تعيين دوره `admin` عبر `POST /admin/users/<chat_id>/role` مع مفتاح الإدارة.

يرسل النظام الرسالة بمعدل آمن أقل من حد تيليجرام، ويقسّم النص تلقائيًا إذا تجاوز 4096 حرفًا، ويعيد في النهاية عدد من وصلتهم الرسالة وعدد حالات الفشل. المستخدم الذي حظر البوت (خطأ 403) يُعطَّل تلقائيًا حتى لا تتكرر المحاولة معه. يمكن أيضًا الإرسال من خارج تيليجرام عبر:

```bash
curl -X POST "$BASE_URL/admin/broadcast" -H "X-Admin-Key: $ADMIN_API_KEY" -H "Content-Type: application/json" -d '{"text":"إعلان"}'
```

### إرسال صورة جماعية

أرسل للبوت **صورة** (وليست ملفًا كمستند)، واجعل وصفها يبدأ بـ `/broadcast` أو `/broadcast_photo`، ثم نص الإعلان، مثل:

```text
/broadcast_photo إعلان مهم للجميع
```

يمكن إرسال الصورة بلا وصف إضافي بكتابة الأمر وحده. صلاحيات المشرف هي نفسها صلاحيات البث النصي. يوجد معالج صور مستقل لأن فلتر `commands` في pyTelegramBotAPI يطابق الرسائل النصية فقط ولا يقرأ وصف الصور.

تستخدم الدالة `broadcast_photo(photo, caption, chat_ids=None, delay=...)` أكبر نسخة من الصورة الواردة عبر `file_id` نفسه لكل مستلم، دون تنزيلها أو إعادة رفعها. تقبل الدالة أيضًا رابطًا أو ملفًا مفتوحًا؛ بعد أول إرسال ناجح تحفظ `file_id` الذي يعيده تيليجرام وتستخدمه لبقية المستلمين. يُرسل أول 1024 حرفًا من الوصف مع الصورة، ثم الباقي كرسائل نصية متتابعة لا تتجاوز 4096 حرفًا لكل رسالة. تُطبّق مهلة الإرسال بين الصورة ورسائل الوصف أيضًا.

تدعم واجهة الإدارة `photo_url` **أو** `photo_file_id` (لا ترسلهما معًا). الوصف اختياري عبر `caption`، أو عبر `text` للتوافق مع البث النصي؛ إذا وُجدا معًا يُستخدم `caption`:

```bash
curl -X POST "$BASE_URL/admin/broadcast" \
  -H "X-Admin-Key: $ADMIN_API_KEY" -H "Content-Type: application/json" \
  -d '{"photo_url":"https://example.com/announcement.jpg","caption":"إعلان بصورة"}'

curl -X POST "$BASE_URL/admin/broadcast" \
  -H "X-Admin-Key: $ADMIN_API_KEY" -H "Content-Type: application/json" \
  -d '{"photo_file_id":"TELEGRAM_FILE_ID","text":"إعلان","chat_ids":[123456789]}'
```

بدون `chat_ids` يكون الإرسال لكل المستخدمين النشطين؛ عند تمريرها تُستخدم القائمة المحددة فقط، والقائمة الفارغة لا ترسل شيئًا. الاستجابة تحتوي `users` و`sent` و`failed` و`deactivated`. يُحسب المستلم ضمن `sent` فقط إذا نجحت الصورة وكل أجزاء الوصف؛ وقد يكون استلم الصورة بالفعل إذا فشل النص اللاحق. خطأ 403 يعطّل المستخدم عبر `db.set_user_active(chat_id, False)`، وتستمر المحاولة لبقية المستلمين. طلب الإدارة ينتظر اكتمال البث قبل إرجاع النتيجة.

### الاختبارات

```bash
pip install -r requirements.txt pytest
pytest test
```

اختبارات الصور في `test/test_broadcast.py` تمر عبر `bot.process_new_updates` مع محاكاة إرسال تيليجرام دون إرسال رسائل حقيقية، وتغطي صلاحيات المشرف، تجاهل الصور العادية، حدود الوصف، إعادة استخدام `file_id`، تعطيل من حظر البوت، وواجهة الإدارة.

أي أمر غير معروف يبدأ بـ `/` يُرد عليه الآن بقائمة الأوامر المتاحة بدل تجاهله بصمت.

ملاحظة: ملف `bot.py` سكربت قديم مستقل لا يشغّله `render.yaml`، ويستخدم قاعدة `users.db` منفصلة ويضبط webhook. لا تستخدمه للإرسال الجماعي؛ النسخة العاملة هي `app.py` بوضع polling.

## متغيرات Render

أضف المتغيرات التالية في Render، ولا تضع القيم داخل GitHub:

```text
TELEGRAM_TOKEN=...
ADMIN_API_KEY=...
ADMIN_CHAT_IDS=123456789
DATABASE_URL=postgresql+psycopg://USER:PASSWORD@HOST/DATABASE
DEFAULT_INTERVAL=1h
ALERT_POLL_SECONDS=60
PAPER_TRADING=true
MAX_RISK_PERCENT=2
MAX_POSITION_NOTIONAL=10000
ALLOW_LIVE_TRADING=false
```

إذا لم يكن PostgreSQL متوفرًا بعد، يمكن استخدام `sqlite:///market_pro.db` للتجربة، لكنه ليس الخيار المناسب لتشغيل متعدد النسخ أو لحفظ بيانات إنتاجية مهمة. يجب التأكد من أن ملف SQLite موضوع على تخزين دائم إن استُخدم مؤقتًا.

## تشغيل Render

استخدم Build Command:

```bash
pip install -r requirements.txt
```

واستخدم Start Command:

```bash
python app.py
```

الخدمة تربط Flask على `0.0.0.0` وتقرأ `PORT`. يجب تشغيل نسخة واحدة فقط من هذا الإصدار لأن Telegram polling وعامل التنبيهات يعملان داخل العملية نفسها. عند التوسع، افصل خدمة Telegram عن عامل التنبيهات باستخدام queue ونسخة worker واحدة.

## وسيط التداول الحقيقي

لا تتم إضافة وسيط حقيقي قبل تحديد المنصة وتوثيق واجهتها. عند اختيار الوسيط، أنشئ Adapter يطبق `Broker.place_order`، واستخدم مفاتيح مخزنة في Render بصلاحية قراءة وتداول فقط، وابدأ بحساب تجريبي. يجب أن تبقى `PAPER_TRADING=true` و`ALLOW_LIVE_TRADING=false` حتى يتم اختبار المصادقة، حجم العقد، الدقة، حالات الرفض، انقطاع الشبكة، التكرار، وحدود المخاطر.

## حدود الدقة

لا توجد واجهة بيانات واحدة تضمن تغطية كل الأسواق بنفس الجودة أو نفس ساعات التداول. لذلك يعرض النظام مصدر البيانات ووقت آخر شمعة، ويمنع التحليل عند نقص البيانات. دعم التنفيذ الحقيقي يعتمد بالكامل على مواصفات الوسيط، مثل قيمة النقطة، حجم العقد، أنواع الأوامر، الحد الأدنى للكمية، والعملة الأساسية للحساب.

هذا النظام لأغراض البحث والتحليل والمحاكاة. أي تفعيل لاحق للتداول الحقيقي يجب أن يكون قرارًا مستقلًا بعد الاختبار والمراجعة.
