# MarketObserver Pro

نظام Telegram متعدد المستخدمين لتحليل الأسواق والتنبيهات والتداول الورقي، مع طبقة وسيط قابلة للإضافة لاحقًا. النسخة الحالية **لا تنفذ تداولًا حقيقيًا** ولا تستخدم أسعارًا اصطناعية عند فشل مزود البيانات.

## ما تم بناؤه

يحتوي المشروع الآن على طبقة أصول موحدة تدعم العملات الرقمية، الفوركس، الذهب والفضة، النفط، الأسهم وبعض المؤشرات، مع أسماء عربية وإنجليزية ورموز مزود البيانات. طبقة البيانات تستخدم Binance للعملات الرقمية عند توفر الرمز، وYahoo Finance لبقية الأصول، مع cache قصير وفشل واضح بدل اختلاق أسعار.

محرك التحليل يحسب RSI بطريقة Wilder، وSMA20 وSMA50 وATR14، ويستخرج نطاق الدعم والمقاومة من آخر 50 شمعة. النتائج وصفية وموسومة بوقت آخر شمعة وعدد البيانات، ولا تعرض وعدًا بالربح.

يوجد تخزين دائم عبر SQLAlchemy يدعم SQLite للتجارب وPostgreSQL عند النشر، ويخزن المستخدمين، اللغة، آخر أصل، التنبيهات، الحساب الورقي، والصفقات الورقية. التنبيهات تقرأ السعر مرة لكل أصل في كل دورة بدل تكرار الطلب لكل مستخدم، وتدعم `/alert`, `/alerts`, و`/cancel_alert`.

يوجد أيضًا `/paperbuy` و`/papersell` لتسجيل صفقات محاكاة فقط. طبقة `Broker` معزولة داخل `marketobserver/broker.py`، وتحتوي حاليًا على `PaperBroker` ورفض آمن لأي وسيط حقيقي غير مهيأ.

## الأوامر الأساسية

| الأمر | الاستخدام |
|---|---|
| `/start` | تسجيل المستخدم وعرض الإرشادات |
| `/analyze BTC` | تحليل أصل محدد |
| `/chart BTC` | إنشاء شارت من بيانات حقيقية |
| `/risk 10000 1 65000 63000` | حساب وحدات نظرية مع سقف المخاطرة |
| `/alert above BTC 70000` | تنبيه عند تجاوز السعر |
| `/alert below XAUUSD 2300` | تنبيه عند هبوط السعر |
| `/alerts` | عرض تنبيهات المستخدم |
| `/cancel_alert 1` | إلغاء تنبيه نشط |
| `/paperbuy BTC 0.01 60000 70000` | صفقة شراء محاكاة |
| `/papersell BTC 0.01 70000 60000` | صفقة بيع محاكاة |

## متغيرات Render

أضف المتغيرات التالية في Render، ولا تضع القيم داخل GitHub:

```text
TELEGRAM_TOKEN=...
ADMIN_API_KEY=...
DATABASE_URL=postgresql+psycopg://USER:PASSWORD@HOST/DATABASE
DEFAULT_INTERVAL=1h
ALERT_POLL_SECONDS=60
PAPER_TRADING=true
MAX_RISK_PERCENT=2
MAX_POSITION_NOTIONAL=10000
ALLOW_LIVE_TRADING=false
```

إذا لم يكن PostgreSQL متوفرًا بعد، يمكن استخدام `sqlite:///market_pro.db` للتجربة، لكنه ليس الخيار المناسب لتشغيل متعدد النسخ أو لحفظ بيانات إنتاجية مهمة. يجب التأكد من أن ملف SQLite موضوع على تخزين دائم إن استُخدم مؤقتًا.

## تشغيل Render

استخدم Build Command:

```bash
pip install -r requirements.txt
```

واستخدم Start Command:

```bash
python app.py
```

الخدمة تربط Flask على `0.0.0.0` وتقرأ `PORT`. يجب تشغيل نسخة واحدة فقط من هذا الإصدار لأن Telegram polling وعامل التنبيهات يعملان داخل العملية نفسها. عند التوسع، افصل خدمة Telegram عن عامل التنبيهات باستخدام queue ونسخة worker واحدة.

## وسيط التداول الحقيقي

لا تتم إضافة وسيط حقيقي قبل تحديد المنصة وتوثيق واجهتها. عند اختيار الوسيط، أنشئ Adapter يطبق `Broker.place_order`، واستخدم مفاتيح مخزنة في Render بصلاحية قراءة وتداول فقط، وابدأ بحساب تجريبي. يجب أن تبقى `PAPER_TRADING=true` و`ALLOW_LIVE_TRADING=false` حتى يتم اختبار المصادقة، حجم العقد، الدقة، حالات الرفض، انقطاع الشبكة، التكرار، وحدود المخاطر.

## حدود الدقة

لا توجد واجهة بيانات واحدة تضمن تغطية كل الأسواق بنفس الجودة أو نفس ساعات التداول. لذلك يعرض النظام مصدر البيانات ووقت آخر شمعة، ويمنع التحليل عند نقص البيانات. دعم التنفيذ الحقيقي يعتمد بالكامل على مواصفات الوسيط، مثل قيمة النقطة، حجم العقد، أنواع الأوامر، الحد الأدنى للكمية، والعملة الأساسية للحساب.

هذا النظام لأغراض البحث والتحليل والمحاكاة. أي تفعيل لاحق للتداول الحقيقي يجب أن يكون قرارًا مستقلًا بعد الاختبار والمراجعة.
